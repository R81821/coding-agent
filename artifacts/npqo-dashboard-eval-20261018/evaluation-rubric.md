# npqo 仪表盘测试评分量表（100 分）

仅按实际代码、页面观察、命令执行回执及交付截图给分。Agent 自述和工作流通过状态不能代替运行证据；本轮新执行和缓存复用需区分。附加功能不作为原题必选要求。

| 项目 | 分值 | 判分依据 |
| --- | ---: | --- |
| 参考图视觉还原 | 20 | 深色与粉色框架 4；顶部卡片、中央房间、下方图表的层级与比例 6；字体、边框、间距和信息密度 6；整体一致性 4 |
| 8 个 Agent 卡片 | 10 | 数量完整 4；名称、角色、指标有区分 3；状态或指标随事件更新 3 |
| 动态金融图表 | 15 | 金融数据表现合理 5；真实持续更新 7；文字、刻度和走势清晰 3 |
| 中央像素房间 | 15 | 房间、工作站、家具层次 5；8 个 Agent 在房间中的对应关系 5；像素风和空间组织 5 |
| 统一模拟事件源 | 10 | 共用生成器或 store 4；事件结构、时序和状态归约清晰 3；卡片、图表、房间消费同一事件且一致 3 |
| 1440 / 1024 / 390 响应式 | 15 | 每个宽度 5：内容完整 3、无非预期横向溢出 1、文字与控件可用 1 |
| 实际运行 | 5 | 成功安装并启动 3；TypeScript 与生产构建通过 2 |
| 实际测试 | 5 | 事件或状态逻辑的有效测试 2；浏览器验证动态与三个宽度 2；无影响使用的运行错误 1 |
| 实际截图交付 | 5 | 三个宽度截图齐全 3；尺寸与真实运行对应 1；提供可访问文件及说明 1 |

不因缺少原题未要求的暂停、重置、导出、主题切换等功能扣分。截图只覆盖一个宽度时，另外两个宽度不能仅凭 CSS 推断通过。遇到权限、模型或工具故障，应分别记录应用本身与模型执行的责任边界；不要将环境故障误报为页面缺陷。
