# 上下文压缩与摘要

压缩容量采用当前模型配置的 `maxContextTokens`。只有 Profile 显式设置 `workingContextTokens` 时才使用较小的工作预算。当前比例为 80% 触发压缩、45% 作为整理目标。

摘要由模型根据提示词生成，长度随需要保留的信息决定。没有摘要专用的固定 token、字符或条目数量上限；请求输出额度只由模型公布的输出能力和实际输入后的剩余上下文决定，不继承主回答的输出预算。

提示词要求保留目标与用户修正、范围和约束、决策及理由、放弃的方案及原因、错误和修复、相关文件与命令、验证结果、证据 ID、已完成和未完成事项、依赖、不确定性及结果未知的操作。摘要使用 `goal`、`constraints`、`decisions`、`evidence`、`completed`、`pending` 六个字段；运行时目标、待办状态和证据引用另外合并保留。

所有将被替换的历史记录按顺序提交，包括最近消息和当前可用的工具结果。整个输入放不下时，按模型容量分批，后续批次携带先前批次的累计摘要。不会因为超过字符限额而跳过记录。单条完整记录或累计状态无法装入实际模型窗口时，明确停止并保留原历史。

45% 是整理目标。较长的有效摘要只要能退出触发区间并满足下一次请求容量，就会保留；不会为了达到该比例而用简化结果替换重要事实。最近记录只有在已参与摘要后才可从工作上下文移除，用户要求仍按原文保留。

每次成功替换工作上下文前，保存独立的原文检查点。生成失败、截断、空输出、格式无效、预算拒绝或归档失败时，不提交摘要替换。所有摘要调用的用量与模型轮次正常计入运行预算。

同一会话的普通新消息沿用上一轮保存的工作上下文，包含用户要求、工具调用与结果、图片和已经采用的压缩摘要；不会每轮重新拼接短版问答，也不再用固定字符数裁剪历史。已有累计检查点时直接继承，避免把已压缩的旧原文重新展开。旧记录按可用检查点恢复，缺少检查点时保留完整请求和已有回复。每轮仍重新建立当前运行状态、权限和工作流，历史运行状态只作为参考数据。独立会话和委派子任务各自维护上下文。

提示词和结构校验不能证明语义上绝对无遗漏。完整来源覆盖、运行状态合并、失败时保留原历史和可恢复的原文检查点共同提供信息保留保障。

每个会话只显示一个数据面板，将总输入缓存命中率、总输入 token、总输出 token 和压缩次数放在一行，并显示当前会话的上下文占用。累计用量汇总会话中的主调用、摘要、评审和子任务请求；上下文占用单独使用最新顶层运行的主调用输入及输出或当前请求估算，不使用累计输入，也不叠加各轮占用。分母来自实际模型容量和显式工作预算，压缩后立即更新。没有新增占用事件的旧运行，按事件顺序读取已保存的上下文调整容量、压缩后 token 和后续主调用用量；不使用当前模型配置改写历史容量。旧记录缺少容量时显示未知，历史尚未加载完整时不显示部分累计数值。

发送新消息或暂停后继续时，保留同一会话已有的有效占用数据。初始化时重新建立的低估算、恢复标记和未返回输入用量的完成事件不能将它清零；实际主调用用量、已提交的压缩或临时运行控制消息的移除可以正常降低占用。历史预览保留必要的用量和调整锚点，补全完整事件后沿用同一计算规则。
