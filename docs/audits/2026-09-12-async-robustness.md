# 异步健壮性与并行优化检查（2026-09-12）

基于 1.4.1 源码检查核心执行、委派、模型请求、任务调度、存储及桌面 IPC。此记录区分已经实现并验证的修复和仍需单独处理的问题，不代表所有并发风险均已消除。

## 已修复

| 路径 | 原问题 | 修复与验证 |
| --- | --- | --- |
| providers/http.ts | 取消发生在 reader.read 等待期间会得到 done=true，误判为成功；提前结束未取消/释放 reader；取消清理失败产生未处理拒绝；DONE 后仍消费数据 | 读取后和同批帧间检查取消；finally 取消未完成流并释放 reader；清理异常被接住；DONE 立即终止。真实 ReadableStream 测试复现旧行为并验证修复。保留原有忽略空诊断帧的行为。 |
| extensions/subagents.ts | 先减少 active 再唤醒 waiter，新请求能抢走名额，破坏 FIFO 并可能超过并发限制；队列无法取消；NaN 和小数限制不合法 | 直接移交名额；排队支持 AbortSignal；移除取消 waiter；执行前再次检查取消；限制必须为 1–8 的整数。覆盖插队、排队取消、移交中取消、预先取消以及名额回收。 |
| core/runtime.ts、core/run-completion.ts | 已取消的父任务仍可能启动子任务；取消时立即拒绝导致 finally 在子任务运行期间清理 worktree；启动失败泄漏监听器；Promise.all 提前拒绝后兄弟任务仍在后台收尾 | 将取消接入实际并发池调用；启动和监听注册在统一生命周期中管理；取消后等待子任务终态再释放目录；所有已提交子任务结算后才返回批次失败。 |
| providers/router.ts | 模型发现逐个等待，一个服务商列表查询失败会中断整个路由 | 最多 4 个 worker 并行发现，仅查询已授权服务商；单个查询失败不排除正常候选；按原配置顺序评分，保留平分时的确定性。 |

委派仍保留先读后写的顺序，非 Git 工作区的写任务仍串行。Git 子任务各自使用隔离工作区。正在执行的操作仍须自行响应其取消信号；并发池只管理排队和名额，不假装可以强制中断任意 Promise。等待子任务终态时不会提前删除其工作目录。

模型发现测试让 9 个列表请求等待同一受控 gate，确认首轮有多个请求实际并行、最大同时在途不超过 4、全部请求完成，且禁止的服务商未被调用。内置服务商当前主要返回本地配置，实际速度收益取决于发现过程是否存在异步等待；没有宣称真实模型任务的加速倍数。

## 检查后确认现有实现正确的部分

- 本地安装的 @earendil-works/pi-agent-core 会逐个 await 事件监听器；并非通常 EventEmitter 的即发即忘语义。桥接测试确认异步检查点写完后才进入验证/返回，回调异常可传播，同步轮次计数先于模型请求。因此未修改这条执行链。
- Pi 工具定义已将只读且幂等的工具标记为 parallel，其他工具为 sequential；没有为提升并发而放开写操作。
- 存储文本事件已按 100ms/4KiB 合并，flush 使用事务，失败保留队列；未发现必须改成多线程写同一数据库的依据。

## 尚未修复的后续项

以下来自代码检查，尚未为这些项建立端到端故障复现，也未在本轮声称修复。

1. **高优先级：完整关停屏障。** runtime.close 只停止 scheduler 定时器，然后关闭 telemetry、数据库和密钥；没有统一等待所有活动 engine run 和 scheduler runner。应先禁止新任务，取消并等待活动任务/回调退出，最后关闭持久化资源。需用关停时仍有工具/模型流的集成测试验证。
2. **高优先级：调度器触发去重与异常收口。** scheduler.tick 在任务很快完成后可能在同一 cron 时间窗口重复启动同一 occurrence；tick 的定时触发和 runner 链也缺少最终异常处理。allowOverlap 的 Running 状态处理和运行计数应一起明确，避免只修一个判断留下状态竞态。
3. **中优先级：worktree 创建失败的回滚。** WorktreeManager.create 在添加 worktree 后若应用补丁/复制未跟踪文件/切换分支失败，没有统一回滚；路径前缀 startsWith 检查应换成路径边界判断。应验证只清理本次创建且归属明确的目录和 Git 元数据。
4. **中优先级：IPC 容量与背压。** daemon 每条输入行都立即分发，缺少帧长度/队列/写缓冲上限；desktop 连接被提前关闭且没有完整响应时会等到请求超时。容量设计应兼顾已有大附件，避免把取消/审批请求堵在长操作后面。
5. **性能边界：** SQLite 大迁移、完整性检查仍含同步阶段；图像附件准备仍主要串行；模型发现接口还没有独立超时/取消参数。后续应先测量事件循环延迟、附件内存峰值和延迟，再选择 worker 或有限并发，不能直接用无上限 Promise.all 代替所有循环。
