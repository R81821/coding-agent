# 聊天撤回

误发送后，先点击暂停，等待本轮显示已暂停，再将鼠标移到本轮用户消息上，点击消息下方出现的撤回图标。图标平时隐藏，键盘聚焦时也会显示。只允许撤回同一会话最新、尚未完成的主对话；已完成、正在运行、等待审批和较早的轮次均不能直接撤回。

等待工具审批时也可以暂停。暂停会保留待审批请求，继续时恢复同一审批；暂停不会授予新的权限或执行待审批操作。确认本轮显示已暂停后，再进行撤回。

暂停后直接发送新消息，会在聊天中新增用户气泡，并自动继续同一任务。模型先结合已有上下文和新消息重新思考，再决定后续操作，无需再次点击继续。消息不会藏在执行过程的折叠区域里；刷新或重新打开会话后仍保留。若消息已保存但自动继续失败，页面显示原因，可以点击继续重试，无需重新发送这条消息。

暂停后发送的新消息也有独立的恢复点。再次暂停且尚未完成时，将鼠标移到最新的用户消息上即可撤回这条消息：消息及其后生成的回复和文件修改会被撤销，发送它之前的对话、文件和子任务继续保留，任务保持暂停。撤回图标只出现在最新消息下方，已完成的消息和缺少恢复点的旧追加消息不能撤回；不会通过撤回整轮来删除此前内容。

撤回首次消息时，本轮及其子任务从聊天记录和后续模型上下文中移除。撤回追加消息时，仅移除该消息之后的分支，并恢复发送前的上下文。撤回的消息回填到输入框；已输入的补充内容会保留，方便修改后重发。累计输入、输出 token、缓存统计、压缩次数及任务预算保留真实消耗。

## 文件恢复

每轮开始执行前在本地保险库保存加密文件快照，暂停完成时冻结本轮结束状态。撤回将工作区恢复到发送前的内容，覆盖新建、删除、二进制和忽略文件，并保留发送前已有的未提交修改与暂存区状态。

恢复前会检查当前文件是否仍与暂停时一致。暂停后手动修改过文件、同一工作区存在交错执行的其他对话、工作区根目录被替换、Git HEAD 或配置等元数据已改变、备份不完整或遇到不支持的文件结构时，撤回会失败并显示原因，对话和输入框保留。缺少完整快照的旧轮次也不能撤回。文件恢复或数据库提交失败时会补偿已恢复的内容；若恢复过程中又出现手动修改，则保留该修改、对话及加密备份，并提示补偿未完成。

文件恢复范围为记录的工作区或 Git 仓库。命令或外部工具产生的工作区外改动、远程消息和已发生的外部服务操作不属于文件快照。

## 持久化

`run.withdraw` 由 daemon 校验轮次、等待主任务及全部子任务停止，再恢复文件，最后提交数据库撤回标记。追加消息通过 `messageId` 指定独立恢复点，同时恢复发送前的检查点、计划和验证记录，移除该消息后新增的子任务及记忆。客户端不能绕过“最新且已暂停”的限制。后台保留加密的真实消耗统计，撤回内容不会重新进入会话历史或模型上下文。
