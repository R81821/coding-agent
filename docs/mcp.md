# MCP 服务接入

MCP（Model Context Protocol）服务接入让 Harness 连接外部工具服务器：在「插件」页的「MCP 服务」标签中配置服务并绑定项目后，该项目内的对话与任务即可发现并调用这些服务提供的工具。调用统一经过既有审批、事件记录、预算与恢复管线，与内置工具一致。

支持三种传输方式：本地 stdio 子进程、远程 Streamable HTTP，以及旧版 SSE 兼容选项。同一项目中来自不同服务的同名工具互不冲突，界面始终显示工具的原名称与服务来源。

典型操作顺序：新增服务 → 填写配置 → 保存（新服务默认停用）→ 启用 → 绑定当前项目 → 测试连接 → 查看工具目录。

## stdio 服务

stdio 服务以本地子进程形式启动，表单字段如下。

- **启动命令**：要执行的命令，例如 `node`、`uvx`、`npx`。
- **参数（JSON 字符串数组）**：必须是合法 JSON 字符串数组，例如 `["server.mjs", "--port", "3000"]`。格式错误时保存会提示「参数需为 JSON 字符串数组」。
- **工作目录（留空使用项目目录）**：不填写时，子进程的工作目录默认为本次运行的项目目录。
- **环境变量**：以「名称 / 值」列表编辑，启动时注入子进程；名称须以字母或下划线开头，且仅含字母、数字、下划线。

所有传输方式共用两个超时设置：

| 字段 | 默认 | 范围 |
| --- | --- | --- |
| 连接超时（秒） | 15 | 0.1–120 |
| 调用超时（秒） | 60 | 0.1–3600 |

## 远程服务（Streamable HTTP 与 SSE）

- **服务地址**：HTTP(S) URL，不允许在 URL 内嵌用户名、密码或 fragment，例如 `https://example.com/mcp`。
- **传输方式**：服务支持当前标准协议时选择 **Streamable HTTP**；仅当服务只提供旧版 SSE 端点时选择 **SSE（兼容）**。
- **请求头**：以「名称 / 值」列表编辑。`host`、`content-length`、`connection`、`transfer-encoding`、`accept`、`content-type` 以及 `mcp-` 前缀的名称由协议自身管理，不能自定义。

## 导入 JSON 配置

「导入 JSON」粘贴包含 `mcpServers` 的配置，先「校验并预览」，确认后再保存。导入的服务一律以停用状态保存，并绑定到当前项目；导入过程不会执行任何本地命令。每条配置需恰好提供 `command` 或 `url` 之一。

```json
{
  "mcpServers": {
    "本地示例": {
      "command": "node",
      "args": ["server.mjs"],
      "env": { "API_KEY": "your-api-key" }
    },
    "远程示例": {
      "url": "https://example.com/mcp",
      "headers": { "Authorization": "Bearer <your-token>" }
    }
  }
}
```

## 认证

### 自定义请求头 / Bearer token

远程服务在保存前于「请求头」填写，例如名称 `Authorization`、值 `Bearer <your-token>`（值为 Bearer 加空格加 token）。

### OAuth

仅远程服务可用，服务卡片上显示「OAuth 登录」按钮。

公共服务无需 OAuth。点击登录时，Harness 会先尝试正常连接；若服务允许匿名访问，页面显示「此服务无需 OAuth 登录，已连接」，不打开浏览器。只有服务明确要求认证时才开始授权流程。Microsoft Learn 的 `https://learn.microsoft.com/api/mcp` 是无需登录的公共服务。

1. 点击「OAuth 登录」，系统在浏览器中打开授权页面。
2. 在授权页面完成授权。
3. 回到 Harness：登录期间页面自动轮询刷新，卡片显示「等待浏览器完成登录」；成功后状态变为「OAuth 已登录」。

- 登录后按钮变为「退出登录」，点击立即清除凭据；登录过程中可点「取消登录」。
- 登录流程 5 分钟内未完成会自动过期，需要重新发起。
- 登录后的 token 支持自动刷新。
- OAuth 凭据保存在加密数据库中，界面只显示登录状态，凭据内容永不回显、不下发。

### 密钥编辑语义

编辑服务时，已保存的环境变量与请求头只显示名称，值不回显。每个条目可选择：

- **保留**：不修改原值；
- **替换**：写入新值；
- **清除**：保存时移除该项。

## 项目绑定语义

- 每个服务的「绑定项目」列表声明它允许服务哪些项目（每行一个绝对路径）。同一服务可绑定多个项目；在任一绑定项目内打开页面，可用「绑定当前项目」把当前项目加入列表。
- 只有绑定的项目能获得该服务的工具：未绑定项目不会出现该服务的任何工具，建立连接会以「服务未对当前项目启用」拒绝。
- 连接按「服务 ID + 配置版本 + 规范化项目路径」隔离。同一服务为不同项目建立各自的连接，roots 只返回本项目的路径。凭据按服务保存，不会暴露给未绑定该项目；同一服务绑定的多个项目共用该服务的一份凭据。
- 停用服务立即阻止新的调用并取消在途调用；删除服务同时取消所有项目的在途调用。

## 风险分类与审批

- 「只读工具名称」列表由用户显式声明哪些远程工具是只读的（每行一个工具名称，需自行确认）。未列入的工具一律按高风险处理。
- 远程服务自带的 `readOnlyHint` 等注解不可信：它们不能为工具授予只读身份，风险等级只由本地配置决定。
- 风险标签不决定是否需要审批：所有 MCP 工具都需通过正常的任务审批流程，外部读取调用同样不能默认放行。审批由项目与任务的既有策略决定。
- 但风险标签并非纯提示：它参与计划审批、只读委派子任务的能力过滤，以及「结果未知的写操作」判定。把实际会写入的工具列入只读，会让该工具绕过计划审批，并且在调用结果未知时不再被记录为不确定。只在你确知该工具不产生副作用时才列入。

## 只读委派子任务

- 委派的只读子任务只会获得只读 MCP 工具：即使父任务使用了写工具，只读子任务也收不到这些写工具。
- 所有子任务都继承父任务冻结的工具目录作为能力上限：父任务没有的工具，子任务无法获得；子任务永远不能扩大父任务的能力范围。

## 大工具目录

一次运行解析出的工具超过 48 个，或工具契约合计超过 80 KB 时，模型只收到两个调度工具，而非完整目录：

- `mcp_search`：按关键词查找工具，返回最多 5 个匹配工具的完整参数 schema；
- `mcp_call`：按 `mcp_search` 返回的工具名称与 schema 发起一次调用。

`mcp_search` 只在本地冻结目录中检索，不发起任何远程调用，因此不需要审批。通过 `mcp_call` 发起的实际调用会还原为原始工具定义，再进入引擎的权限与执行关卡，与直接调用走完全相同的审批管线。

## 诊断与常见问题

服务卡片的状态含义：

| 状态 | 含义 |
| --- | --- |
| 已停用 | 服务未启用，不建立连接、不提供工具 |
| 未连接 | 已绑定当前项目但尚未建立连接 |
| 连接中 | 正在建立连接 |
| 已连接 | 连接正常，卡片显示工具数量 |
| 需要登录 | 远程服务要求 OAuth 认证；401 等认证失败显示此状态，不会静默降级为匿名连接 |
| 连接失败 | 连接或握手失败 |

- **连接失败 / 服务不可用**：卡片显示「连接失败」及原因；任务入口同时提示「MCP service unavailable; check its connection and authentication in the plugin page」。检查命令可执行、URL 可达、绑定与启用状态，并用「测试连接」验证。
- **认证失败**：OAuth 未登录或 token 失效时状态为「需要登录」，需重新登录或更新请求头。登录失败提示「MCP OAuth login failed; try signing in again」。
- **运行中配置变更**：任务运行期间服务配置被改动（配置版本、工具 schema 或权限范围变化），恢复时拒绝沿用旧配置，提示「MCP configuration changed since this run started; start a new task to use the new configuration」；契约变化的工具不会按旧审批被静默调用。请新建任务以使用新配置。
- **写入结果未知**：写调用在传输层失败且无法证明远端未执行时，调用**不会重试**，运行将其记录为结果不确定并中止该操作。请先在远端检查实际状态，再开始新操作。
- **未绑定项目 / 服务停用**：该服务在当前项目不提供任何工具。先「绑定当前项目」并勾选「启用此服务」，再测试连接。
