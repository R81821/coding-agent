# 回答质量与任务流程优化：实现与验证

日期：2026-10-18。对应方案：[agent-behavior-optimization-plan.md](agent-behavior-optimization-plan.md)。

## 已实现的行为

新任务默认使用 `behaviorPolicyVersion: 2`。`auto / analysis / change` 仍是用户入口，不新增关键词分类器，也不以请求中是否出现“实现”来判断任务。

- **咨询**：先给结论、推荐路线、理由与限制。自动模式不预载完整 DAG / 修复循环，不以无关仓库测试作为方案依据。未开始项目工作时不注入根目录清单；受信任项目约定仍保留其作用域。
- **只读命令与探查**：风险和权限单独检查。调用终端、创建 todo 或保存方案不会因此产生源码验收义务；完整工作区快照决定实际影响。
- **小修改**：允许直接进入轻量路径；真实代码修改必须有相关测试、当前完整 diff 和逐项需求证据。权限、迁移、存储等已识别的高影响路径，以及配置要求的扩大验证，仍需通过相应检查。路径规则只是保守提示，不是完整语义风险分析；模型和项目检查还需覆盖实际业务影响。
- **文档**：未配置明确测试契约、未建立实施图时，纯 Markdown / RST 或 docs、notes 下的文本交付使用内容、引用、格式与当前 diff 验收。代码、配置和依赖清单继续要求测试；一旦该任务已有源码修改，不能通过随后改文档免除验证。
- **复杂任务**：保留依赖图和节点验收。配置图不等于执行图；开始节点、调度写任务或检测到真实改动后建立相应义务。图内已有的必需检查不会因轻量路径而被免除。
- **未知影响**：超时、异常和恢复时未确认的非幂等调用保留 unknown。普通读取不清除该状态。缺少工作区检查工具时报告具体阻碍，避免反复要求模型调用不可用工具。

上述改动没有放宽工具授权、路径约束和显式 analysis 模式的写入限制。依赖图从来不是权限凭据。

## 提示词、记忆和角色

核心指令优先处理当前问题；实施提示随实际意图加载，完整图说明只在已有图或兼容策略中加载。没有增加默认的第二次模型润色请求。

桥接层将当前 system 和 developer 消息分别交给 Provider 接口。恢复时重新组装当前策略，不把已保存的系统文本再叠加成新指令。最终 HTTP 格式仍由各 Provider 适配器负责，不能把内部角色分离等同于所有远端模型都原生支持 developer 角色。

长期记忆提炼保留用户明确给出的适用范围，避免将一次测试要求推广为所有任务的规则。对“所有任务都测试”等过宽的已批准记忆，附带来源与范围审查提示；原始记录保持原样，冲突必须明确说明。

固定 system/developer 指令字符数实测：

| 模式 | 字符数 |
|---|---:|
| 改动前默认现代工作流 | 9,830 |
| 新自动模式初始请求 | 3,968 |
| 减少 | 59.63% |

统计拼接后的指令正文，不含消息分隔符、工具 schema、项目规则、历史和附件；这是字符数，不是 token，也不是质量或总费用测量。

## 验证回执

跨 local / broader 阶段可以引用同一次适用套件执行。复用要求完整依赖分析与执行条件一致；依赖指纹包括环境、命令、工作目录、stdin、超时和预期退出码。opaque / 不完整依赖仍实际执行。`force=true` 要求实际重跑。

实际执行记录 `executionId`；引用保留原执行 ID、`reusedFromRunId` 和 `reusedFromItemId`。新增阶段引用不代表新增执行或扩大覆盖。较新的失败不能被更旧的通过掩盖。检查点回执指纹还包含当前进程环境，避免恢复后错误复用。

## AGENTS.md 与旧任务

新生成的 AGENTS.md 将测试要求限定到实际代码 / 配置修改，并分别说明咨询、文档与界面交付。

项目检查返回已知旧模板的迁移预览。桌面项目规范入口和 Web 项目确认对话框可以审阅、应用更新，再重新信任新哈希。仅完全匹配旧模板的正文和明确托管的记忆后缀可自动处理；混合手写规则拒绝自动替换。预览过期、链接目标和内容变化会被拒绝。

迁移保留已同步记忆的来源指纹，但不自动信任新文件。用户重新信任准确的迁移结果后，记忆删除、过期或内容变化仍会使对应托管内容失效，避免旧偏好残留生效。

已只读核对 `D:/hello/AGENTS.md`：匹配可迁移模板。该文件尚未被改写，需要在项目规范入口应用更新并确认信任。已有信任不会因程序升级而自动扩大。

没有版本信息的旧检查点继续使用兼容策略 1，不在缺乏证据时自动降为咨询。恢复保留实际 revision、已改文件、目标、权限、预算及有效回执；扩大验证义务不因恢复丢失。API 的 `RunSpec.behaviorPolicyVersion` 可显式选择 1 或 2。选择版本不删除工作记录、不清除 unknown，也不清除已建立的图；版本 1 是流程兼容选项，不是旧安装包或旧提示词的逐字回滚。

## 运行诊断与配对评测

`model_request_finished.requestDiagnostic` 记录 Provider 边界上的实际模型 ID、思考档位、输出上限、消息与工具数量、各类文本字符数，以及工具定义和附件清单哈希。不记录提示词正文、密钥或附件字节。

这不是最终 HTTP 请求抓包：服务商的端点映射、对不支持参数的转换仍需结合 Provider 配置检查。未记录的参数不能假定与另一客户端相同。

已提供 30 类固定任务和评测工具：

```powershell
node --experimental-strip-types scripts/behavior-eval.mjs cases
node --experimental-strip-types scripts/behavior-eval.mjs prepare samples.json NEW_REVIEW_DIRECTORY
node --experimental-strip-types scripts/behavior-eval.mjs report adjudicated.json
```

`samples.json` 为 `BehaviorSample[]`，类型见 [behavior.ts](../packages/evals/src/behavior.ts)。每题每组至少三次，使用唯一真实 runId；`requestSettingsHash` 对实际端点、模型、思考和生成参数做规范化哈希，`inputFixtureHash` 对原问题、附件内容、工具可用能力、项目初始快照和会话起点做规范化哈希。不要将凭据写入数据文件。策略文本本身属于实验变量，不能要求其哈希相同。

`prepare` 拒绝缺失、重复或输入不一致的样本，随机交换 A/B，生成 `blind-pairs.json` 和独立保管的 `private-key.json`。原答案可能透露客户端风格，随机化并不保证完全消除识别偏差。

人工阅读 blind-pairs 并填写 `BehaviorReview[]`；每对保留一份汇总后的人工裁定。`adjudicated.json` 包含 `{ samples, key, reviews }`。报告按问题聚合三次重复，包含完成率、质量、无关测试、事实错误、时间和用量；模型评分不能替代人工放行。合格结果仅为 `eligible_for_release_review`，仍需结合回归和实际交付检查。

**尚未完成真实模型质量盲评。** 当前只有原先两份答案，缺少当时完整原问题、原始图像输入和两边真实运行载荷；没有将合成测试当成 DeepSeek 质量测量。30 题 × 两组 × 三次的真实执行、人工评分和服务商参数核对仍是发布质量判断前的待办。

## 验证记录

基线四组测试 35 项通过。实现后的检查覆盖纯咨询、只读命令、实际终端写入、权限拒绝、显式 analysis 限制、文档验收、未知影响、旧检查点、跨阶段复用、force / 环境失效、模板迁移、角色分离和评测放行约束。

最终冻结源码后的全量回归：214 个测试文件、1,986 项测试全部通过（209.68 秒）。迁移与记忆边界的专项回归 22 项通过；全量结果已包含最终修复。测试日志保存在本地 `.cache/behavior-release-regression.log`。

类型检查与修改文件的 ESLint 检查通过。桌面渲染器、Electron 主进程与 preload、Web、守护进程均构建成功；Electron 隔离启动检查确认主进程、preload 与解锁界面正常加载，未显示窗口或访问用户保险库。

本轮只更新源码和构建产物；现有 1.4.52 安装包不包含这些新改动，需另行打包。真实模型盲评与人工评分仍待执行，不能由上述工程检查推断回答质量已经达到发布门槛。
