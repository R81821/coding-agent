# Harness Agent 1.4.0-beta.3

1.4.0 批次一的第三个预发布版本：修掉 1.4.0-beta.2 之后在真实使用中发现的界面与协议缺陷。相对 beta.2 只动了 4 个源文件（外加测试），不含新功能。

## 修复

### 审批弹窗内容一长就无法作答（界面）

- 审批遮罩是 `position: fixed` + `place-items: center` 且**不能滚动**，弹窗面板又没有高度上限。当年弹窗从 `.approval-dialog`（自带 `max-height: min(760px, calc(100vh - 56px)); overflow: auto`）改用 `BuiGlassPanel` 时，这层保护被丢掉了。
- 实测（真实 Chromium，90 项验证入参）：弹窗高 **10,489px**，在 712px 视口里「批准一次 / 拒绝」被顶到 y=10429，鼠标与滚轮都够不到 —— 运行就卡在一个没人能给的批准上。
- 现在：遮罩 `place-items: safe center` + `overflow-y: auto`，面板 `max-h-full flex flex-col overflow-hidden`，内容区 `min-h-0 flex-1 overflow-y-auto`，命令预览 `max-h-[40vh]`。同样内容实测按钮落在 y=552，无需滚动即可点击。
- 「审批」标签页有同样缺陷且更糟：它直接 `JSON.stringify` 原始入参、**完全不截断**，现已与弹窗共用同一个带上限的预览函数。

### 被截断的回答被报成不可理解的失败（协议）

- 线上报 `Responses stream did not complete: {"reason":"max_output_tokens"}`，随后运行直接结束。两个缺陷叠加：
  - 主循环每轮请求的输出上限实际是 **4096**：`min(8192, 估算输出, 上下文×比例)` 里估算值被硬编码为 4096，是三项中的最小值，于是 **8192 天花板从未生效**，长分析或长脚本必然被截断。
  - Responses 适配器把「被截断」与「请求失败」放在同一分支，直接抛错并打印供应商原始 JSON，既不说原因也不说怎么办。
- 现在：估算值提到 8192（天花板生效；小上下文模型仍由比例项保护）；`response.incomplete` 与 `response.failed` / `error` 分开处理，明确报出撞到的是哪个上限以及可行的下一步。
- 已知同类隐患（未改，已记录在台账）：Chat / Anthropic / Gemini 三条路径忽略自己的截断信号（`finish_reason: "length"`、`stop_reason: "max_tokens"`、`finishReason: MAX_TOKENS`），在那里被截断的回答会被当成完整回答。

## 验证

- 门禁：`pnpm run typecheck`、`pnpm run lint`、`pnpm run test`（49 文件 / 297 用例）、`pnpm run build` 全部通过。
- 两处修复都有反证：撤掉源码改动，对应测试立刻变红 —— `expected 4096 to be 8192`；截断那条旧代码输出 `Responses stream did not complete: {"…`（正是线上看到的原文）。
- 审批布局用真实 Chromium 做新旧对照实测（不是目测）。
- 打包内容审计：daemon 标记 **21/21**、样式表标记 **2/2**、运行时 WAL 写入/读回、daemon 端到端启动（`health: ok`，版本 1.4.0-beta.3）。
- 未包含（与 beta.2 相同）：批次二界面其余项、检查点引用化、消息与大输出内容去重、流式增量合并、6 步运行时迁移；安装包未签名，界面安装流程未执行（改为审计打包内容 + 实启 daemon）。
