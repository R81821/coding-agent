# Harness Agent 1.4.5：测试文件与逐项需求验收

按用户要求取消自动独立模型评审，将当前真实测试、完整 diff 和逐项需求证据作为验收依据。测试失败和证据过期进入修复与复测循环，继续直到通过；不能把失败伪装成完成，也不能为了通过删除有效断言。本次只修改源码与验证，不生成安装包、不替换已安装应用。

## 当前流程

1. 理解需求，记录稳定验收 ID，并根据仓库架构规划实施步骤。
2. 将断言写入真实 test 文件，配置项目原生测试入口，以套件批量执行用例。
3. 按步骤实施并执行局部测试，再执行计划中的集成测试。
4. 失败时诊断并优化代码或测试；证据过期时重新跑套件，保持原有需求与有效断言。
5. 重新读取当前完整 diff，通过 `check_requirements` 为每条需求提交当前观察、实际通过的测试运行和 diff 证据。
6. 逐项验收后输出最终报告，不再调用独立审核模型或重写第二篇长结论。

现代验证入口拒绝 stdin 及 Python/Node 内联断言执行，提示先写测试文件。旧工作流保留自身主模型需求核对和 final review；所有版本均不再自动触发独立模型审核。暂停、取消、权限或总预算不足仍记录真实未完成状态。

## 桌面与配置

Profile 页保留主回答最大输出 token 编辑，留空默认 393,216，包含推理 token，保存后影响新运行。移除独立评审策略选择和审核输出 token 输入；历史 `reviewPolicy` 与 `reviewMaxOutputTokens` 数据保留兼容，不在编辑其他设置时清除。

进度改为局部验证、集成测试与逐项需求验收。失败显示“待修复重测”，过期显示“待重新验证”；有 runId 的历史独立评审记录仍显示为历史信息，不当作当前门槛。报告仍由结构化运行状态决定是否完成。

前一审核证据修复中的原始证据回查、缓存来源确认、准确停止原因和报告正文去重继续保留。独立审核调用、等待与拒审反馈循环已由本策略替代。历史会话及原始事件不改写。

## 回归覆盖

测试用例写入 Vitest test 文件，由 `pnpm test` 批量执行。覆盖不再发起审核请求、逐项验收的真实测试与当前证据要求、失败修复与过期复测、内联测试拒绝、配置兼容、主输出额度编辑和桌面状态展示。完整验证结果由本次执行日志记录。

2026-10-09 最终验证：`pnpm test --maxWorkers=2` 全量 **121 个测试文件、883 项测试通过**，用时 140.08 秒。类型检查、相关修改文件 ESLint 和 `git diff --check` 均通过。测试覆盖了代码修复、错误测试修正、过期证据补充、同轮重复套件复用，以及验收耗尽最后一次模型或工具额度后仍能正常输出最终报告。

常规并发的全量检查曾出现 3 项本地 MCP 连接失败；对应 2 个测试文件的 15 项批量复测通过，随后降低并发的完整套件全部通过。验证日志保存在仓库根目录 `.test-acceptance-tests.log`、`.test-acceptance-tests-initial.log`、`.test-acceptance-mcp-recheck.log`、`.test-acceptance-typecheck.log` 和 `.test-acceptance-lint.log`。
