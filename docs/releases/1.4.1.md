# Harness Agent 1.4.1

修复 1.4.0 首次迁移大历史库时，桌面固定30秒启动截止提前终止daemon的问题。

## 诊断依据

用户生命周期日志在2026-09-11 21:19、21:29和21:30附近记录 daemon-timeout 后 SIGTERM；SQLite只有实验特性提示。原库约746MB，对应迁移备份/暂存文件已生成但未切换。日志另有几次明确口令校验失败，属于不同错误。本次没有读取口令、解密用户历史或修改实际库。

## 修复

- 备份、复制、转换、校验和切换阶段发送脱敏进度；逐检查点报告完成数。
- 普通启动仍为30秒；有效迁移进度允许继续等待，连续5分钟没有进展或总计30分钟才超时。重复/倒退计数、普通stderr和SQLite警告不会无限延长等待；口令错误即时报告。
- 转换由全量加载旧检查点改为按ID逐条读取、转换和校验，仅保留当前记录。保留逐条深度等价校验、最新恢复点校验、总数与SQLite完整性检查、原库/备份保护。
- 生命周期日志记录迁移阶段与进度，超时信息明确区分迁移未完成和普通启动失败。

## 验证范围

合成旧库746852352字节、2120个检查点，在96MiB堆限制的子进程完成迁移；Node24基准约11.3秒，采样峰值79615224字节。此结果用于验证大库内存边界，不代表真实用户库迁移耗时承诺。具体测试及打包运行时结果见发布清单。

保留原口令和现有备份。请退出旧版后安装1.4.1，再使用原口令解锁；首次迁移期间等待完成。没有自动删除先前中断留下的暂存文件或备份。

最终验收：57个测试文件、339项通过，类型检查/lint/构建/包内协议与原生模块检查/临时daemon健康检查均通过。随包Node22复测同一合成库约12.8秒，采样堆峰值60196348字节。安装包未签名，见[发布清单及SHA-256](./1.4.1-manifest.json)。单次备份、复制或完整性检查在极慢存储上超过5分钟，仍可能达到停滞上限，未宣称适用于任意大库。
