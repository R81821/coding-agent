# Harness Agent 1.4.0

本次基于 1.4.0-beta.3 补齐升级审计发现的实现缺口。

## 改动

- 运行：记录源码和验证命令指纹；验证期间或评审后源码变化使通过凭据失效。同阶段不同测试保留，模型重试计入预算。所有修改任务由独立模型逐项核对需求，分析任务不额外固定调用评审。
- 分析：probe 使用 Docker 的只读仓库挂载、无网络、非特权用户和临时内存目录。缺少 Docker 或镜像时返回配置错误，绝不退回宿主机执行。
- 上下文：限制状态投影，按内容校验复用读取证据；压缩保留原始需求、已完成事项和已有决策，超过压缩预算时明确停止而不发送超限上下文。
- 存储：加密消息/输出去重，检查点保存引用；按运行索引后解密；文本最多按 100ms/4KiB 批量提交，工具/授权/完成边界立即刷新。文本不再产生强制刷新的逐片 trace。
- 迁移：保留旧密钥和数据目录，在暂存库转换、校验后切换；迁移前备份不自动删除；旧会话缺项增量回填。永久删除会话只回收该会话独有内容，保留共享及无关对象。
- 界面：自动/分析/修改模式、API协议和显式上下文容量设置，真实待办/文件/验证状态，按主循环/压缩/评审显示用量与实测请求耗时；未知费用显示未知。
- Provider：四类接口的明确长度截断信号作为错误返回，保留已有文本和用量。

## 验证

- 全量离线回归：57 个文件，331 项通过。测试并发限制为 4，避免密码派生与真实进程/SQLite夹具争用导致的5秒超时；没有放宽产品预算或测试断言。
- 独立审查发现的文本批处理、验证项覆盖、永久删除引用残留问题均已修复并复核。
- 旧库迁移、失败保留/重试、WAL恢复、共享对象保护使用合成临时数据库测试。没有迁移或清理用户实际数据。
- 类型检查、lint、构建、Windows x64打包、包内原生模块/WAL读写及无provider的临时目录daemon启动均通过。安装包未签名；SHA-256与文件大小见 [发布清单](./1.4.0-manifest.json)。

## 使用与验收范围

分析 probe 需要已运行的 Docker 和预先安装的镜像；默认 node:22-bookworm-slim，可用 HARNESS_PROBE_IMAGE 指定。容器中 /workspace 只读，/probe 可写，使用 Linux 命令。程序不会自动拉取镜像。自动/修改模式仍使用经授权的宿主机工具。

兼容接口设置可显式选择 Responses 或 Chat Completions，也可保持自动协议；上下文容量应按供应商实际值填写。未配置时仍采用兼容默认值 128000，这不是已确认的模型上限。

真实模型三次对照测试、缓存命中率目标和5分钟耗时目标尚未测量；没有产生真实模型调用费用。Docker边界有离线参数/拒绝宿主写入测试，未完成有可用镜像的容器内集成验收。UI已做组件渲染测试，未进行人工完整界面验收。

100ms刷新受事件循环调度影响，突然终止最多可能丢失一批尚未提交的文本；正常结束/读取/关闭会刷新。保留的迁移备份不随会话永久删除自动清理。迁移故障和事务回滚已有测试，物理断电、重命名瞬间断电和真实磁盘耗尽未做硬件故障注入。
