# Harness Agent 1.4.5：审核证据与待验证状态修复

后续按用户要求取消自动独立模型评审，当前策略见 [测试文件与逐项需求验收](./1.4.5-test-acceptance.md)。本文件保留前一修复的定位与验证记录，以下独立审核流程描述不再代表当前运行策略。

修复“修改待验证或缺少当前证据”不能解释实际停止原因，以及现代工作流审核缺少原始证据、拒审反馈未交给主模型的问题。审核真实不通过继续阻止完成；当前代码版本的真实测试通过记录保留，补证和代码修复分别按各自门槛处理。

## 本次定位

会话“分析代码，并在内置浏览器打开html文件”停止时使用了 64/64 模型轮次和 77/128 工具额度。期间三次审核正常返回不通过，原因包含 HTML 与浏览器原始证据未提供给审核、以及修改 `_verify_pelican.py` 与已记录的 req-4“不修改源码”要求冲突；本次不是审核输出 token 截断。

实现缺陷包括：审核证据包主要由 diff 引用构成，未覆盖当前原始代码读取和浏览器操作；不通过的逐项需求 verdict 未完整保留；拒审通过通用失败路径清空真实通过的验证，工作记忆又缺少具体拒审理由。主模型因此无法按准确反馈纠错，预算耗尽后只留下统一提示。修改审计脚本与只读要求的冲突仍是需要处理的事实，不能据此认定所有审核判断都错误。

## 修复内容

- 现代审核提供当前 epoch/revision 下成功、完整的原始读取、搜索及浏览器工具结果，另提供完整 diff 与真实验证记录。缺失原始记录时明确返回缺失项。
- 读取缓存按原始证据 ID 解引用，并确认参数一致、内容未变及来源完整；保留当前观察与原始来源关系，避免将缓存提示当作代码正文。
- 浏览器截图的文本审核输入保留来源、元数据、字节长度和校验摘要，不发送 base64 图片正文。元数据证明截图已取得，不冒充模型已经看过图片或通过视觉审核。
- 审核不通过时保留总理由和逐项需求 verdict，交给主模型具体纠错。`read_evidence` 可分页回查工具、验证、审核和失败记录。
- 现代拒审保留当前有效的局部、集成、步骤验证与完整 diff，只清除需求和报告审核的通过标记，继续阻止完成。真实文件修改、执行失败、未确认执行影响及恢复仍按原规则使验证失效。
- 相同报告未补证或修正时不再次发起相同审核；保留拒审原因，避免消耗轮次却没有进展。
- 模型轮次与工具额度耗尽分别记录准确停止代码和具体未完成门槛，避免统一显示“修改待验证或缺少当前证据”。

保留工作流自身审核；Profile 未配置或选择“不额外启用”仍不会关闭该审核，也不会新增第二次 Profile 审核。旧工作流的失败诊断和完整失效行为保持兼容。前一修复包的输出额度设置、停止指令生命周期和报告重复输出修复继续保留。
