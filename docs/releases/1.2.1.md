# Harness Agent 1.2.1

修复仓库分析任务反复读取、耗尽工具额度后只显示失败的问题。

- 将实际的 Windows PowerShell 5.1 环境和预算写入初始上下文，优先使用文件检索工具。
- 每轮附带剩余调用额度及最近 12 条工具观察；相同读取连续三次得到相同结果时停止探索。工具结果变化或执行可能改变工作区的操作后，重新计算重复次数。
- 工具批次在执行前检查额度，不执行超额调用。探索停止时在剩余轮次内使用禁用工具的请求整理发现；无剩余轮次时提供确定性操作记录。未完成任务保留为 review，不宣称 completed。
- 保留 read_file 等工具异常的具体诊断；终端非零退出码与超时进入失败恢复逻辑。
- 工具结果写入 Agent 历史后再保存批次检查点，避免该检查点缺少刚完成的结果。
- 验证修复不再突破模型轮数上限，发生模型错误后不再继续发起修复请求。
- 最终答复仅使用完成回合；过程记录可展开查看。终端失败在工具列表中显示为失败。

保留 64 次默认工具额度。本版本没有实现完整 Repository Map、语义索引、OS sandbox 或全部 Context Compaction 改造。截图本身无法证明每次重复调用的原因；上述相关缺陷已用本地可重复测试验证。

验证：类型检查、lint 通过；全量 26 个测试文件、91 项测试通过，其中新增 12 项循环收敛回归测试。
