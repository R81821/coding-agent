# 对话完整内容自动加载

2026-10-07。本次调整取代前两批中“预览截断 + 用户点击加载”的设计。

## 页面行为

- 桌面端和 Web 端不再提供“加载完整回答与执行记录”“继续加载执行记录”“加载更早的消息”“查看工具输出”“继续加载输出”等数据加载按钮。
- 打开会话后自动读取全部轮次、执行记录和工具输出。当前可见轮次及附近轮次优先，未显示部分继续在后台预加载。
- 回答不再截断到 16,000 字符；正在运行的回答也不再只保留末尾 100 条文本增量。桌面工具详情不再截断到 20,000 字符。
- 保留原有执行过程/工具详情的展开收起，以及对话虚拟列表。折叠只影响渲染，完整数据仍会自动预加载；展开不需要点击额外的数据加载入口。
- 同步期间可继续阅读；失败会自动退避重试，连续三次失败后显示错误和重试入口，不会静默把缺失数据当成完整内容。

## 性能实现

共享 `SessionContentLoader` 在桌面和 Web 的会话状态层调度读取，最多两个请求并发，每批调度之间让出主线程。执行记录每次最多 200 条，输出每次最多 64,000 字符，这些分页仅是内部传输机制。历史补齐后只替换对应轮次，并保留其间到达的新事件和状态，避免重复拼接聚合预览。离开会话后停止后续调度并忽略迟到结果；全部完成后不再轮询历史内容。

虚拟列表继续仅挂载可见范围及缓冲区，完整数据不会同时变成整页 DOM。未变化轮次保留引用，待加载工具输出列表按事件数组缓存；Markdown 和工具文本复用渲染结果。

会话 LRU 大小估算由整段 `JSON.stringify` 和 UTF-8 拷贝改为对不可变对象的缓存估算，减少切换时的大块字符串分配。上限仍是六个会话、约 12 MB 的保守估算值，当前活动会话的数据不受该历史缓存上限裁剪。

后端为工具输出增加解密后文本的 LRU：最多 16 个输出、合计 8,000,000 个字符。相邻分页复用解密和格式化结果；新工具结果、删除、清除和数据库关闭时失效。读取缓存前仍检查会话/项目可见性。大于单项上限的输出仍完整提供，但不驻留该缓存。

## 验证

- 全量 `pnpm exec vitest run --maxWorkers=2`：112 个文件、717 项测试通过，耗时 98.77 秒；日志位于 `.cache/auto-content-tests.log`。
- 真实 Electron 冒烟验证通过：主进程、预加载和构建后的页面文档成功加载。
- 类型检查、修改文件 ESLint 和构建通过。
- 新增调度回归覆盖可见优先、自动补齐旧轮次与长输出、并发限制、切换后的迟到结果、历史与实时增量合并、失败退避及游标续传。
- 数据库回归验证 120 条文本增量（24,000 字符）全部保留，长回答不截断；连续输出分页不再重新解密内容对象。
- 实际 Web 组件夹具：25 轮、5050 条事件全部自动读取；超过 16,000 字符的回答和 70,008 字符的输出保留结尾；没有手动加载按钮；完成后没有重复请求；当时仅挂载四行。展开执行过程后验证了工具输出末尾也在 DOM 中。
- 导航延迟响应夹具再次通过，确认自动预加载未破坏导航隔离、失败恢复、实时事件游标和断开清理。截图位于 `.cache/auto-content-regression.png`。

复现：启动 `pnpm --filter @harness/web dev`，打开 `/tests/auto-content-harness.html`，点击“运行回归”。数据均为合成数据，不访问实际会话。

完整活动会话仍需要相应的数据内存，超大单轮内容内部尚未单独虚拟化。本次没有用真实大历史库测量端到端 P95 延迟；不把功能回归或并发限制当作实测延迟提升。
