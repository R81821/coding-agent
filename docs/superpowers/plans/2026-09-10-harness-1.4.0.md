# Harness 1.4.0 完整优化计划

## 一、目标与实施原则

保留现有 TypeScript/Electron 架构，迁移 Hermes 的轻量工具设计，完成 Agent Loop、上下文、DeepSeek 适配、验证、界面和增量存储改造。

以“检查 memory 模块，分析得出可优化方案”这次真实运行作为回归基线：修复分析任务被转成修改任务、状态重复发送、频繁压缩和验证反复失效的问题。

已确定的约束：

- 不接入 Hermes Python 运行时，不照搬它的身份提示词或审批策略。
- 保留同一 session 的连续对话、项目归属、删除恢复和独立记忆。
- 工具调用上限保持 128，模型调用上限保持 64，修复次数不设上限；辅助模型请求也计入预算。
- 保留现有权限检查，不把任意终端命令降级为只读。
- 先交付循环与缓存优化，再交付存储迁移；每阶段独立验证。
- 实施前保存当前修改基线，保留此前尚未提交的修复。

## 二、Agent Loop 与工具改造

### 阶段 1：分离分析、探针和源码修改

增加 `RunSpec.taskMode: auto | analysis | change`，默认 `auto`，输入区域提供模式选择。

- `analysis`：允许读取和受控探针，不允许修改仓库源码。
- `change`：执行修改流程，要求验证和最终 diff 检查。
- `auto`：依据实际操作进入对应流程；不能因为调用 terminal 就改成修改任务。
- 原有请求仍默认 `auto`，不创建新 session。

将三个概念分开记录：

| 概念 | 用途 |
|---|---|
| 权限风险 | 决定是否允许执行、是否需要审批 |
| 执行影响 | 区分读取、隔离探针、仓库写入、未知影响 |
| 仓库版本 | 决定哪些代码证据和验证结果失效 |

具体规则：

- 文件编辑成功且内容实际变化后，才递增仓库版本。
- 普通终端查询不能直接递增版本。
- 任意脚本仍按现有权限策略执行；执行前后检测工作区内容变化。
- 临时实验放入独立探针目录，单独记录副作用和错误。
- 已经存在的脏文件也比较内容，不能只比较 `git status` 文件名。
- 无法确定执行影响时记录“影响未确认”，要求检查，不能直接宣称修改或验证通过。

完成条件分开：

- **分析任务**：已有可引用证据、给出结论与优化建议、说明未检验范围；不要求为不存在的源码修改完成测试矩阵。
- **修改任务**：相关验证通过、最终 diff 已检查、需求已核对；实际相关变更才使验证失效。
- 探针失败可以修复，也可以放弃并降低结论置信度；不能无限阻塞分析报告交付。

### 阶段 2：拆除模型侧的大型 `update_workflow`

新运行不再向模型公开 `update_workflow`。采用以下工具边界：

| 工具 | 职责 |
|---|---|
| `todo` | 维护少量任务及 pending/in_progress/completed/cancelled 状态 |
| `search_files` | 搜索文件名或内容，支持结果分页 |
| `read_file` | 按行读取，返回行号、截断状态和下一页位置 |
| `patch` | 局部修改，复用现有补丁校验与路径约束 |
| `terminal` | 执行命令，保留 stdin、超时和退出状态 |
| `run_verification` | 执行明确的验证命令并生成运行时收据 |
| `read_evidence` | 按证据 ID 读取已保存结果，避免重新执行工具 |

工具行为固定：

- `todo` 支持按 ID 合并更新，最多 20 项、每项最多 300 字符；更新返回变更项与计数，按需查询完整列表。
- 简单分析无需先调用 `todo`；复杂任务用它维护计划，不用它证明业务完成。
- `read_file` 默认 200 行，上限 2,000 行，并受 64 KiB 输出预算限制；截断时给出 `nextOffset`。
- `patch` 保留已有 Git 补丁能力和局部替换校验，不用整文件覆盖替代局部修改。
- 工具失败返回简短结构化诊断和结果引用，不返回完整运行状态。
- 工具定义在一次运行内冻结，名称排序、描述和 JSON 序列化稳定。

旧工具名称保留兼容映射，用于旧 Profile、历史查看和恢复；映射共享原权限约束。旧运行恢复时转换状态，未确认完成的非幂等调用仍暂停复核，不能自动重放。

需求、观察、修订和验证收据继续由运行时维护。模型不再手工填写大量内部 ID，也不能通过把 todo 标记完成绕过修改任务的验证。

## 三、上下文、模型与验证改造

### 阶段 3：建立可控的工作上下文

上下文分为固定前缀、基准快照、增量事件和近期消息：

- 固定前缀只包含安全规则、Profile 提示词、编码行为及工具定义。
- 项目路径、状态、预算、时间和 diff 放入上下文消息。
- 基准快照只保留项目概况、任务目标、当前计划和必要约束。
- 完整观察、命令输出和历史 diff 保存到证据存储，按需读取。
- 工作状态投影默认不超过约 2,048 tokens，不重复发送全部 observations。

修改差量协议：

- 按观察 ID 和递增序号发送新增、更新、撤销与失效信息。
- 移除滑动数组导致整组 `set` 的行为。
- 未变化字段不发送。
- `read_evidence` 能检索较早证据，不再因只保留最后 32 条观察而迫使模型重读。
- 证据有效性绑定文件内容及相关环境指纹；未知影响触发复查。
- 将 `read_range` 和兼容读取工具纳入重复检测；相同内容优先引用已有结果，不直接中止整个任务。

### 阶段 4：重做压缩与 DeepSeek 适配

**上下文预算**

- 区分模型硬容量与 App 工作预算。
- DeepSeek 使用已核对的模型元数据，未知兼容模型保留可配置的保守值。
- 默认工作预算 128K；80% 触发压缩，目标压至 45% 以下，同时预留输出空间。
- 只估算真正发给供应商的内容，不把 Pi 内部 `content/details` 副本重复计数。
- 结合服务端实际 input_tokens 校准估算误差。

**压缩规则**

- 先精简过期工具内容，再执行摘要。
- 摘要保存目标、约束、决定、有效证据引用、已完成事项和待办。
- 保持工具调用与结果配对；固定前缀保持不变。
- 摘要输出上限实际传到供应商，默认 2,048 tokens。
- 拒绝空摘要、纯工具调用文本、DSML 标记和结构不完整摘要；使用运行时事实生成确定性回退。
- 单次压缩失败不进行反复模型重试。
- 压缩后的模型上下文与完整审计历史分开保存，检查点不能把未压缩历史重新装回模型。

**供应商接口**

新增明确配置：`apiProtocol: chat_completions | responses`，不再把“兼容 OpenAI”当成完整能力描述。

- DeepSeek Chat 路径传递正确输出上限，保存并按官方规则续传推理状态；推理内容不混进普通回复 UI。
- DeepSeek 与 OpenAI 的 Responses 路径均测试工具续接、稳定 instructions 和 `previous_response_id`。
- 本次已使用官方 DeepSeek 地址的默认配置，升级后在新运行启用经验证的 Responses 路径；运行中的旧请求不切换协议。
- 自定义兼容地址保持原协议，避免擅自切换不支持的服务。
- 关闭连续响应时使用完整本地上下文与 `store=false`。
- 响应 ID 过期时，仅在没有输出、没有执行工具前回退完整请求；不得重放工具。
- 缓存 key 继续使用应用版本与仓库身份，不加入 run ID 或时间。
- 主循环、摘要、评审分别统计用量；未知缓存、推理或费用字段显示未知，不填成零。

### 阶段 5：可靠验证与结果展示

`run_verification` 接收命令、工作目录、超时及可选 stdin；运行时记录执行内容指纹和关联代码版本。

- `python -` 等依赖 stdin 的验证必须提供脚本；否则返回配置错误，不执行空验证。
- 配置错误不计为代码修复失败。
- 通过依据是真实执行结果；无关读取不能使结果失效。
- 只有未解决且影响交付的失败阻止完成；放弃的探针必须在报告中说明限制。
- 对重大修改保留独立评审；普通分析不增加固定评审模型调用。

界面同步调整：

- 分开展示“任务计划”“实际修改”“验证结果”，分析任务不显示虚假的修改版本。
- 缓存统计分主循环与辅助请求，显示累计输入、命中、未命中和覆盖率。
- 展示模型阶段、工具、审批、压缩的耗时；只有有准确计时的数据才标为纯请求耗时。
- 区分“分析已完成”“修改待验证”“缺少配置”“额度耗尽”。
- 内部状态和收据默认折叠，最终回答突出结论、依据、建议及限制。

## 四、增量存储、迁移与发布

### 阶段 6：替换 SQL.js 全库导出

采用当前 Electron 已验证支持的 `node:sqlite`，保持现有业务数据库接口，使用 WAL、短事务和索引查询，移除定时同步导出整库的路径。

数据拆分：

- 消息及大型工具输出独立加密保存，重复内容去重。
- 检查点保存消息引用、上下文快照引用、事件游标、预算和待确认调用。
- 为检查点、验证及证据建立 run/session 索引；先按运行查询，再解密，避免扫描全部历史。
- 普通文本流按最多 100ms 或 4 KiB 合并持久化；工具发起、授权、结果和完成状态在边界立即提交。
- 保证工具发起记录先落盘，再执行副作用；崩溃恢复不自动重放未知结果的写操作。
- 运行时不再为每个工具阶段保存完整 transcript。

迁移规则：

1. 关闭旧数据库写入并刷新，检查可用空间，生成完整备份。
2. 在暂存数据库中迁移，保留原加密边界和会话 ID。
3. 将旧检查点转换为可还原的引用结构，不删除对话、回收站或记忆。
4. 校验数据库完整性、记录数量、历史内容和最新恢复点。
5. 校验通过后原子切换；失败时继续使用原库并显示迁移错误。
6. 迁移前备份不自动删除；回滚需明确使用备份，不能静默覆盖迁移后产生的新数据。

新增版本化接口包括任务模式、轻量进度事件、执行影响、证据引用、上下文快照引用及分类请求用量。旧记录仍可读取；旧 IPC 历史查询保持兼容，由数据层按需还原内容。

### 分阶段发布

- 第一批：任务模式、轻量工具、上下文、DeepSeek 和验证优化。
- 第二批：增量存储、旧库迁移、恢复与发布验收。
- 最终版本定为 **1.4.0**，生成 Windows x64 安装包、SHA-256 和发布清单。
- 每批仅在对应回归通过后提交；不把未完成迁移混入可安装版本。

## 五、测试与验收标准

### 必须通过的离线回归

- 同题分析运行终端查询后仍保持分析模式，不产生虚假 revision。
- 修改已有脏文件可检测；无变化补丁、只读查询不使验证失效。
- 隔离探针失败可诊断或放弃，不强制进入源码修复。
- 超过 32、64、128 条观察时，仅发送增量；较早证据仍能查询。
- `update_workflow` 不再出现在新运行工具清单；工具定义跨轮稳定。
- 长任务多次压缩后，目标、证据、工具配对和待办保留，旧完整历史不重新注入。
- 无效 DSML 摘要回退；摘要和主模型的输出上限进入实际请求体。
- DeepSeek 推理状态续传、Responses 工具续接、过期 ID、异常中断及 stateless 模式均有协议测试。
- 空 stdin 验证被拒绝；真实测试通过后只因相关变化失效。
- 64 次模型、128 次工具和无限修复配置保持正确，辅助请求不漏计。
- 迁移后会话、项目、回收站、记忆和历史回复一致；断电、取消、磁盘不足及迁移失败可恢复。
- 长任务检查点不再复制整段历史；不再存在全数据库 export/writeFileSync 热路径。
- 完整测试、类型检查、lint、构建、安装包启动和旧数据升级检查通过。

### 实际效果验收

先使用本次轨迹建立离线长回归；真实模型对照测试作为显式启用的独立步骤，不在单元测试或构建中自动调用。

同模型、同推理档位、同仓库快照重复至少三次，分别报告冷启动和后续请求，不只挑最好的一次。

目标：

- 同题分析主模型请求不超过 25 次，工具调用不超过 50 次。
- 主循环累计输入不超过 100 万 tokens。
- 主循环缓存命中率达到 85% 以上。
- 同题任务压缩不超过 1 次。
- 正常服务延迟下，耗时中位数目标不超过 5 分钟。
- 输出覆盖记忆质量、长期记忆、存储与并发、实施优先级，并明确未验证项。
- 必须正常交付分析方案，不能依靠“额度耗尽后的最后摘要”完成回答。

这些是需要测量验证的目标，不是预先保证。任何提速若依赖丢失必要证据、跳过真实验证或破坏历史数据，均不算验收通过。
