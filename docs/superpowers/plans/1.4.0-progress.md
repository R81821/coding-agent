## Review fixes applied on top of the batch

- `packages/core/src/pi-agent-bridge.ts`: `contextPolicy.workingContextTokens` needed
  `| undefined` under `exactOptionalPropertyTypes`, which was the only failing typecheck.
- Unconfirmed execution effects were silently cleared by the next read. `effect: "unknown"` is now
  sticky until a successful repository recheck or a confirmed write, and `compareWorkspace` records
  any observed content difference as a repository write even when a snapshot is incomplete, so a
  real edit can no longer escape the repository revision.
- `verify()` reported a missing verification configuration by aborting the whole run; it now returns
  a structured `verification_config_missing` item and keeps the remaining items running.
- `z.toJSONSchema` must be called with `{ io: "input" }`. The output-mode schema marked every
  defaulted field as required, and the wire-layer validation therefore hard-rejected the natural
  `read_file { path }` call; `search_files`, `todo` and `run_verification` were affected as well.
- Runtime-owned tool exemptions are driven by declared risk plus an explicit
  `ToolDefinition.selfAuthorized` marker instead of a hardcoded name allowlist.
- Observations are bounded instead of unbounded on the modern path (32 legacy, 512 schema v3).
- A thrown tool failure carried no result reference: pi turns the exception into a bare error
  message, so the model lost the `evidenceId` pointer that structured failures already had. The
  modern path now returns the same envelope and the failed call stays retrievable through
  `read_evidence`; the legacy path still throws on purpose.

## Live acceptance run against the packaged pre-release

- 2026-09-10: the plan's analysis prompt (`检查memory模块，分析得出可优化方案`) was run in the installed
  `1.4.0-beta.1` on real models, routed as `openai-compatible / deepseek-v4-flash`. It reached 22
  model turns and 38 tool calls with a 92.3% input-cache hit rate over 19/19 reported requests
  (553,089 input tokens, 510,592 cached) and made no repository change (`修改版本 0`), so the analysis
  stayed read-only as required. Estimated cost stays unknown rather than zero.
- The run exposed two runtime defects, both fixed here:
  - `verify()` could publish `verification_started` and then escape (budget, cancellation or a storage
    failure) without ever publishing `verification_finished`, so `localCheck`/`broaderCheck` kept
    their default `pending` for the rest of the run. The model read that as a harness-level "running"
    state, burned two self-correction attempts on it and ended the analysis through raw `terminal`
    calls that each needed a high-risk approval.
  - The interactive approval a verification needs was waited on with a flat 15-minute broker TTL that
    ignored the run's own duration budget, so an unanswered approval could outlive the run it belongs to.
- Fixed in `packages/core/src/engine.ts`: `verify()` now wraps the check loop and always publishes one
  terminal run (persist, emit `verification_finished`, record on the workflow, best-effort checkpoint)
  before rethrowing, and `authorizeTool` accepts an approval TTL that the verification path bounds by
  the remaining run duration. `tests/engine-modern-140.test.ts` adds the regression; it fails without
  the engine fix (`verification_started` 1, `verification_finished` 0) and passes with it.
- Root cause of the underlying abort, not fixed here: the daemon process died while exporting the
  entire `harness.sqlite` (648 MB) for a checkpoint, leaving `harness.sqlite.5836.tmp` behind and no
  daemon socket, which froze the run and produced the UI's `connect ENOENT` error. Every checkpoint
  still rewrites the whole database; that is the stage-6 redesign listed above as not started.
- 2026-09-10 gates after the fix: `pnpm run typecheck` clean, `pnpm run lint` clean,
  `pnpm run test` 47 files / 287 tests passed, `pnpm run build` succeeded.
