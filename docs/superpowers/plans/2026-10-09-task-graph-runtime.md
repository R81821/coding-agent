# 任务图运行时：修改步骤

目标：补齐图节点并行执行、测试依赖分析、长任务恢复和自主下一步选择。保留现有授权、暂停、真实测试和需求验收，不打包，不启用独立模型评审。

1. 扩展兼容协议：节点优先级、执行方式/文件范围、自主选择策略、持久化子任务记录；检查记录增加依赖范围、依赖指纹和来源；检查点保存已消耗活动时长及批量测试进度。
2. 实现自主选择：LLM 可以显式选择下一步；未指定时根据已验证依赖、优先级和关键路径选择可执行节点。只有实际结果改变验证状态；旧有序检查点维持原策略。
3. 实现图任务并行：将可执行节点映射为有界子任务，同步真实子任务运行 ID 和状态；读取并行，独立写任务使用包含当前脏文件的 Git 工作树。范围冲突或不明确时串行；增量产物由父任务授权合并并验证。
4. 分析测试依赖：解析测试入口和静态依赖，合并显式范围及项目配置；无法确认范围时保守退回全局。复用只来自持久化真实通过结果，并校验测试配置、环境及全部依赖指纹；相关变化重新执行。
5. 增强长任务恢复：预算累计活动时间，停驻时间不计费；每个测试结果及子任务状态持久化。恢复核对工作区、配置及真实子结果，复用确认的完成项，不重放未知写入。用户显式新一轮续跑仍可以获得新预算。
6. 接通模型运行时：更新旧固定流程提示，提供图状态、行动选择、恢复进度和测试复用原因，使模型可自行决定实施、并行、修复、复测及验收顺序。
7. 用 test 文件验证：真实并发与互斥、Git 脏基线和增量补丁、依赖变化与选择性执行、数据库重启和部分套件恢复、预算及未知调用，再运行全量测试、类型检查、lint、diff 检查。

范围边界：并行子任务产物不是通过证据；文件范围不能扩大权限；依赖不完整不能宣称覆盖；恢复不是自动取消用户暂停或重发未知非幂等调用。

## 实施记录（2026-10-10）

步骤 1–6 已完成。新图默认自主选步，兼容旧有序/手动检查点；选择建议按优先级和关键路径排序，模型仍可选择任意依赖满足的节点或调整图。

`run_tasks` 把节点映射到真实子运行，最多 8 并发（默认 4）。Git 写任务继承父工作区已有改动，在独立工作树中执行，返回仅包含子任务新增改动的标准 Git 补丁；冲突范围、未知范围及非 Git 共享写入串行。父任务合并产物后仍需实际测试与需求验收。

测试依赖分析覆盖测试入口、静态导入、项目脚本、配置、显式输入及执行环境。完整且未变化的依赖可复用数据库中的实际通过记录，结果标出来源；不完整分析重新执行。较新的失败回执覆盖旧成功回执，`force=true` 可要求新执行。

每个套件结果保存检查点，暂停在套件边界停止；恢复仅继续未完成项。工作树基线也持久保存，进程退出后可从真实停驻子任务恢复新文件和二进制增量产物。恢复会核对真实父子身份、目录及写入范围，不自动合并、不重放未知写入。

同一运行恢复已消耗的活动时间、轮次、工具调用和费用，暂停时间不计入时长；子任务消耗同时计入父预算，恢复补回漏记部分并防止重复计入。显式创建新 continuation 才取得新预算。
