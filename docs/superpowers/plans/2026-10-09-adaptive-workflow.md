# 状态更新与自主规划：实施步骤

目标：LLM 决定任务理解、计划调整、步骤选择和恢复策略；运行时继续掌握实际写入、测试结果、权限、暂停及最终完成。保留旧调用和检查点兼容，不启用独立模型审核，不打包。

实施状态：以下 7 步均已完成，源码及测试已冻结后通过全量验证。

1. **修正验收契约与证据复用。** 只读验收允许使用当前完整阅读/探针证据；变更验收仍必须引用真实局部和集成测试及完整 diff。为 diff 关联运行时工作区指纹，相同指纹的完整证据可跨测试调用顺序复用。拒绝失败、截断、未知及过期证据。
2. **统一任务进度。** 执行步骤自动投影到 todo，额外事项保留；查询不发布状态变更。模型不能用 todo 的 completed 覆盖运行时 verified。
3. **增加原子规划和局部重规划。** `advance_workflow` 保留原动作，新增一次提交理解、架构、计划的动作及局部计划更新。更新前完整校验，失败不留下半份计划；文本/顺序调整保留有效步骤和测试配置，增加或改变检查只失效相关计划进度及需要重新满足的全局验收。
4. **按依赖安排步骤。** 新计划默认允许选择无依赖的步骤，支持明确 dependsOn、切换和合并实施后批量验证。旧检查点仍按原顺序运行。允许提前运行集成测试；最终完成仍要求所有步骤有真实验证、当前局部与集成结果及逐项需求验收。实际代码变化继续保守失效全局验证，不假设已经具备测试依赖分析。
5. **分类处理可恢复错误。** 已确认无写入的参数、读取/搜索和补丁校验错误保留通过的测试；测试失败、真实写入和未知影响仍进入修复/复测。旧工作流保留兼容行为。
6. **提供可选择的行动建议。** 状态投影输出建议动作、原因、可开始步骤和缺少的完成证据，保留 nextAction 兼容。Auto 模式可显式声明只读意图，已发生写入、已有变更计划及显式 change 模式不能被模型降级逃避验证。
7. **批量验证与记录。** 用实际 test 文件覆盖上述行为、历史兼容、权限/暂停和真实进程测试；先执行相关套件，再执行全量 test、类型检查、lint 和 diff 检查。失败时修复实现或错误断言，保留有效验收边界。

验收重点：无效规划不改变已接受状态；计划调整不伪造测试；无依赖步骤可以合并实施，有依赖步骤受依赖约束；只读验收不强求无法执行的测试；同一代码证据不因调用顺序而被强迫重读；暂停、权限及完成证据的控制权不交给模型。

## 已实施的接口与行为

- `advance_workflow action=configure` 原子提交 `summary`、`requirements`、`architecture`、`evidenceIds`、`steps` 和 `integration`，可选无前置依赖的 `startStepId`。所有证据、测试入口、依赖图和起始步骤先校验，再一次更新状态。
- `action=update_plan` 必须给出 `reason`；可提交步骤 upsert、`removeStepIds`、`integration` 和 `mode`。提交步骤的顺序在前，剩余原步骤保留相对顺序；同 ID 省略 `dependsOn` 会保留原依赖。悬空依赖、环、自依赖、重复 ID 或非文件测试均原子拒绝。
- 新计划默认 `mode=adaptive`；缺少模式字段的旧检查点解析为 `ordered`。无依赖步骤可以切换实施，局部验证覆盖全部已启动步骤，相同套件只实际运行一次并为各步骤保留独立结果。集成测试可提前运行，但不代替步骤验证。
- 单纯需要复测时可直接运行实际套件；`reopen_step` 用于重新编辑及重置依赖进度，复测无需先虚构一次代码重开。
- 步骤文本、顺序不改变测试契约时保留 `verificationKey` 和实际回执；检查或依赖变化会重置该步骤及其依赖后继，无关步骤保留。实际写入仍使全局验证失效，完成前重新批量运行测试。
- 步骤自动映射 todo，额外手动事项保留；查询和同值更新不发布变更，todo 不能伪造步骤通过。状态投影提供 `availableSteps`、`suggestedActions`（含原因）、`completionBlockers`，旧 `nextAction` 保留。
- Auto 模式可在尚无计划、实际写入或未知影响时用 `understand intent=analysis` 确认或纠正只读判断。显式 change、已有计划和实际写入不能被降级。
- `check_requirements` 的只读证据可省略测试和 diff 引用；变更仍需当前真实局部、集成测试和完整 diff。运行时为完整稳定 diff 绑定代码指纹，相同指纹可跨测试顺序复用；模型不能提交或伪造该指纹。
- 显式验收的解析错误与拒绝都会清除旧验收并发布当前状态；只读最终结论不能覆盖该拒绝。已确认无写入的读取/搜索和补丁校验失败保留真实测试；测试失败、写入和未知影响仍失效。未知影响只能由运行时完整稳定检查解除。
