# 外部 MCP 与项目任务、工具、技能协同设计

日期：2026-09-21
状态：MCP 架构待用户审阅；已修复独立发现的任务运行和技能搜索基线错误，MCP 产品代码尚未实现。

## 目标与完成定义

用户目标：达到可接入外部 MCP 和项目任务完美配合，tool 和 skill 能发挥好，达到 Codex 基础的地步。

这里将“基础”落实为可检验的产品行为：用户在桌面端配置外部服务、选择项目及工具，模型在该项目的对话和任务中根据技能正确发现、调用工具，结果进入上下文和运行记录；权限、取消、超时、重启和恢复均有明确行为。页面存在或单独连接成功不构成完成。此定义不声称与 Codex 产品全部功能或模型能力等同。

## 当前证据

- `apps/desktop/src/renderer.tsx` 的 `PluginsView` 只有本地 harness-plugin.json 安装、信任、启停。
- `packages/extensions/src/plugins.ts` 使用自定义 tool.execute RPC，不是标准 MCP。
- `packages/core/src/runtime.ts` 的 `profileFor` 为交互入口添加已启用插件工具，但调度器直接读取原始 Profile；委派任务也需要统一检查能力继承。
- `packages/core/src/engine.ts` 在运行开始构建工具集合与技能上下文；已有运行审批、工具事件、checkpoint 和输出证据，可复用。
- 技能支持来源区分、会话选择、内容信任以及恢复时冻结选择；需补充与 MCP 的行为集成验证。
- 当前工作区有大量既有未提交修改，应原地增量实现并保留已有工作，不从 HEAD 新建一个遗漏这些修改的实现基线。
- 2026-09-21 初检：TypeScript 检查通过；技能会话集成测试失败，最后一次模型请求只有历史摘要。后续定位表明这不是技能断言取错请求：固定 393,216 输出额度被从 128,000 模型上下文中全量扣除，导致可用输入仅剩 1 token，主请求无法开始。
- 完整基线 445 项中 68 项失败。2026-09-22 修复输入预算与输出上限的耦合，并补上搜索凭据校验及无效配置时的已有 GitHub 后备检索。原技能会话测试未删改，其恢复和技能隔离验证重新通过。新增 8 项输出/上下文集成测试；独立审查后统一压缩与发送估算，最终 453 项全量测试、类型检查和构建通过。详见 `docs/audits/2026-09-22-mcp-runtime-baseline.md`。

## 方案比较与选择

1. **推荐：标准 SDK + 原工具执行管线。** 新增独立 MCP 服务层，将外部工具适配为现有 ToolDefinition；复用审批、事件、证据、预算和工作流。改动跨协议、存储、运行时和界面，但只有一套执行语义。
2. 将 MCP 塞进原插件进程协议：开始较快，但连接、鉴权、工具更新和项目作用域混在原插件信任模型中，后续更难验证。
3. 单独做一个独立 MCP 聊天执行器：界面容易展示，任务和技能却走另一套链路，不满足本目标。

## 外部服务与连接

- 使用官方 TypeScript SDK，安装时确认可用稳定版本并锁定实际依赖。支持本地 stdio、远程 Streamable HTTP；提供显式旧版 SSE 兼容选项。
- 表单支持服务名称、传输方式、本地命令与参数、环境变量、远程地址、认证配置、连接和调用超时。
- 支持常见 mcpServers JSON 配置导入；导入先校验并展示内容，不自动执行本地命令。
- 认证覆盖自定义 header/Bearer token；对 OAuth 服务提供登录、回调、刷新和退出流程。认证失败明确显示，不错误回退成匿名连接。
- 保存、修改、启用、禁用、删除、连接测试、重连、工具刷新均提供可见成功或错误状态。进程关闭时释放连接和本地子进程。
- 连接按服务配置版本及规范化项目路径隔离。stdio 使用明确 cwd，roots 返回本运行项目；不能把 A 项目路径通过共享连接暴露给 B 项目。
- 启动不依赖所有外部服务在线；运行准备阶段连接选定服务，部分服务失败不能阻塞整个应用。任务所需工具缺失时明确报告，不能假装调用成功。

## 持久化和项目选择

- 协议新增 MCP 配置、公开状态、工具目录与 RPC 类型；存储使用现有加密数据库，旧数据无配置时默认空集合。
- 服务配置与项目绑定分开；同一服务可以绑定多个项目，但授权和运行连接按项目隔离。
- 凭据只在需要执行时解密。列表 RPC 不返回 secret 值，编辑用“保留 / 替换 / 清除”语义；日志、错误、模型上下文和配置导出不携带密钥。
- 运行开始保存实际采用的服务配置版本、工具契约摘要与技能引用。恢复不能静默改用不同服务、schema 或更宽权限。
- 禁用或删除立即阻止新的调用；进行中的调用取消并清理，UI 明确显示影响。

## 工具接入与任务一致性

- 工具名称使用稳定的服务命名空间与防碰撞映射，满足模型接口的名字限制；用户看到原工具名称和服务来源。
- 完整处理 tools/list 分页、空目录、非法 schema、重复名称和 list_changed 通知。目录变更对下次运行生效，当前运行契约保持稳定；被移除工具返回明确错误。
- ToolDefinition 保留参数 schema、说明和调用超时；文本、structuredContent、资源链接与多媒体结果保留其类型。大内容保存为证据/附件，提供按需读取，不将二进制 base64 填满模型上下文。
- 常规数量工具直接供模型使用；大目录按项目过滤并提供搜索/按需加载，避免因 schema 挤满上下文而失去使用能力。
- 手动对话、暂停恢复、定时任务、远程入口和委派任务使用同一能力解析入口。子任务只能继承父任务已允许的能力，只读子任务不得获得写工具。
- 调用的风险由本地授权配置决定。服务返回的 readOnlyHint 等 annotations 仅供参考，不能自行提升信任或绕过审批。默认未知外部工具按需审批，用户可明确授予项目级工具权限。
- analysis/plan 限制同样适用于 MCP；write/high/destructive 通过现有审批和运行政策处理。外部读取也可能有数据外发，不能直接套用“本地只读默认放行”。
- SDK 调用使用运行 AbortSignal 和超时；用户取消、服务断开、服务返回 isError、传输错误分别记录。未知结果的写操作不得自动重试，checkpoint 恢复不得重复执行。

## 技能协同

- 保留显式选择技能与冻结引用的现有语义，先修复/确认现有集成测试。
- 模型获得可信技能目录与清晰来源，支持按任务发现及按需读取已信任技能；未信任技能不能通过自动匹配被提升为开发者指令。
- 技能正文按用户选择或任务相关性加载；用户的显式选择优先，后续上下文压缩与恢复保留已加载技能的身份和必要规则。
- 技能引用的脚本和资源按来源路径解析，不依赖恰巧与项目相同的 cwd；实际执行仍使用工具和审批管线。
- 显示当前任务已采用的技能、外部服务和可用工具；缺失的依赖工具提供可操作提示。
- 集成场景必须证明：项目技能要求调用指定 MCP 查询工具，模型收到技能与工具定义，真实 MCP 收到调用，返回结果进入后续模型上下文并影响任务产物。

## 页面

- 插件页分为“本地插件”和“MCP 服务”，沿用现有视觉组件，抽出独立组件避免继续扩展 renderer 大文件。
- MCP 页提供新增/编辑/导入、项目绑定、连接状态、工具列表及搜索、工具授权、认证、启停和删除。
- 每个操作有 pending/error 状态，禁止重复提交；表单校验在启动子进程或网络请求前完成。
- 项目任务入口显示当前生效服务/技能和连接失败信息；运行轨迹能对应到服务、工具、输入、结果、时长和审批。

## 分阶段交付与验收

以下阶段共同构成目标，不以任一阶段完成代替整体完成。

1. 协议与存储：配置校验、旧数据兼容、重启持久化、公开 RPC 密钥脱敏、导入错误行为测试。
2. 真实传输：SDK 测试服务通过 stdio 和本地 HTTP 运行；握手、分页发现、调用、结构化结果、认证失败、取消、超时、断开重连、进程清理测试。另验证 OAuth 生命周期和 SSE 兼容。
3. 运行集成：同名工具隔离、A/B 项目权限隔离、工具变更、审批拒绝零执行、只读模式、定时任务和恢复不重复写入测试。
4. 技能集成：原有技能测试全部通过；模拟可控模型 + 真实 MCP + 项目技能的完整运行；技能目录按需加载、压缩恢复和资源路径测试。
5. 桌面验收：实际页面完成新增、连接、选择工具、绑定项目、错误修正和启停；检查布局、键盘操作和状态反馈。
6. 完整验证：pnpm typecheck、相关测试、全套回归及应用构建；对出现的旧问题标出来源并处理与本目标相关的阻塞。提供用户可复现的接入指南和任务示例。
