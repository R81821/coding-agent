# 项目与会话切换优化：第三批

实施于 2026-10-06，最终验证于 2026-10-07。覆盖桌面端和 Web 端的长会话渲染、滚动状态与隐藏页面开销。

后续调整（2026-10-07）：数据读取已改为[完整内容自动加载](session-full-content.md)，移除手动加载及正文截断，保留本批虚拟列表与渲染优化。

## 已落地

- 新增共享的 `@harness/conversation-ui` 包，两端使用同一套动态高度虚拟列表，仅挂载视口附近的消息轮次。固定 `@tanstack/react-virtual` 为 3.14.13；每条消息使用稳定的运行 ID。
- 支持向前加载历史时保持阅读锚点；处于底部时跟随新轮次和流式文本增高；阅读历史时不自动拉回底部，并提供“回到最新消息”。
- 按会话保存滚动偏移、测量尺寸和底部状态，最近六个会话采用 LRU 保留，避免所有访问过的会话都积累尺寸快照。
- 行内状态放在当前会话的内存容器中。消息滚出视口再回来时，已加载的历史、工具输出、分页游标、续办说明、展开状态和待完成操作仍可恢复。离开整个会话后释放该容器；不写入浏览器持久存储。
- 桌面端为未变化的轮次保留对象引用，缓存用量计算；续办父运行的用量变化仍会更新累计值。两端对消息组件做 memo，Web 回答 Markdown 单独 memo。空的增量轮询保持视图引用，避免无数据变化的刷新。
- 桌面端执行过程、工具组和工具详情折叠时不构建内部组件；Web 执行过程按展开状态计算和渲染。正文与执行过程分开更新。
- 桌面设置、代码差异及 Web 工作台工具面板按需加载。桌面技能页首次访问后才挂载；安装任务运行时继续轮询，空闲时没有轮询计时器。隐藏浏览器面板停止 DOM/尺寸观察器，保留任务主动打开浏览器所需的状态订阅。

- `pnpm typecheck` 通过。
- 本批修改文件的 ESLint 和 `git diff --check` 通过。
- `pnpm build` 通过。桌面设置模块 27.75 kB，代码差异模块 3.46 kB；Web 工具面板模块 12.91 kB。引入虚拟列表后，桌面主 JS 为 850.08 kB（gzip 260.63 kB），与前两批的 849.44 kB 基本持平，不将本次按需加载描述为主包显著减小。构建仍有主包超过 500 kB、第三方 PURE 注释位置的非阻断提示。
- 定向回归 33 项通过：包含折叠过程零构建、空轮询不更新视图、终态正常传播、旧轮次引用保持、续办用量正确失效。

- 前两批的导航延迟响应夹具再次通过：立即选择、后一次导航优先、缓存预览、过期响应隔离、失败重试、静止会话无轮询和断开清理。
- 实际 Web 演示页面验证了会话显示、切换后草稿恢复以及设置面板按需加载。

复现：运行 `pnpm --filter @harness/web dev`，分别打开 `/tests/virtualization-harness.html` 和 `/tests/navigation-harness.html`，点击各自的回归按钮。两个夹具仅使用合成数据。虚拟列表截图保存于 `.cache/phase3-regression.png`。

## 边界

虚拟化以消息轮次为单位；单个已展开的超大轮次内部没有再次虚拟化。侧栏继续使用第二批的分页读取。浏览器原生全文查找只能搜索当前挂载的消息，不能覆盖离屏全文。

此次验证证明了挂载范围和交互正确性，尚未在真实大历史数据库上测量端到端 P95 切换延迟，也未完成安装版 Electron 的人工验收。工具输出仍在用户点击读取时解密单个完整输出对象。修改和构建产物保留在工作区，未打包安装或替换正在运行的客户端。

## 后续启动修复（2026-10-07）

开发脚本原先通过 `NODE_OPTIONS=--import=tsx electron src/main.ts` 加载源码，用户启动时出现主进程 `ERR_INVALID_RETURN_PROPERTY_VALUE`，调用栈指向 tsx 的 load hook。现在先用 tsup 编译主进程和预加载脚本，再以 `electron .` 读取包的 JavaScript 入口；Electron 子进程不再注入 tsx，开发服务固定在 5173 端口，等待两个入口文件就绪。

新增 `pnpm --filter @harness/desktop smoke`。它构建桌面端，并使用真实 Electron、隔离的临时目录验证主进程导入、预加载和页面文档加载；禁用测试中的开机启动注册，不解锁实际数据。构建产物与本地 Vite 服务入口均通过此验证。该检查不代表安装版或所有界面交互验收。
